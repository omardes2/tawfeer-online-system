# وكيل المبيعات الذكي — المواصفات والتشغيل

**الموديول:** `AiAgent` (امتداد للصندوق الموحّد — المتطلّب 2.9)
**المرحلة الحالية:** 1 — واتساب فقط
**الحالة:** قيد التنفيذ

---

## 1. النطاق

**داخل المرحلة 1:** استقبال رسائل واتساب عبر WhatsApp Cloud API · تخزين المحادثات
والرسائل في الصندوق الموحّد · وكيل يردّ بالعربية الفلسطينية عبر Claude API
باستدعاء أدوات · أدوات تقرأ من قاعدة البيانات مباشرةً · مسودّة طلبٍ ثم تأكيد ·
تحويل لموظفة بشرية · شاشة «معرفة المنتج البيعية».

**خارجها:** ماسنجر · إنستغرام · التعليقات · الشات المباشر · الردود الصوتية ·
البحث الدلالي · التوزيع التلقائي · حملات المتابعة الاستباقية.

---

## 2. المبادئ غير القابلة للتفاوض

1. **مصدر الحقيقة قاعدة البيانات لا النموذج.** يُمنع أن يذكر الوكيل سعرًا أو
   توفّرًا أو مدّة توصيلٍ أو رقم طلبٍ إلّا نتيجةً مباشرة لاستدعاء أداة. فشلت
   الأداة أو رجعت فارغة ⇒ يسأل أو يحوّل.
2. **المبالغ `decimal(15,2)`** كبقية النظام (مبدأ 5 في `CLAUDE.md`). ويُستثنى
   `agent_runs.cost` بـ`(15,4)` — تكلفة API بالدولار بكسورٍ دقيقة، وهي ليست من
   نقود المتجر.
3. **كل كتابة مالية أو مخزنية داخل `DB::transaction`.**
4. **الوكيل لا ينشئ طلبًا مباشرة.** مسودّة ثم تأكيدٌ بعد موافقةٍ صريحة في
   الرسالة.
5. **صلاحياته: قراءة + مسودّة + تأكيد + تحويل.** لا حذف ولا تعديل ولا إلغاء ولا
   استرجاع ولا خصم يدوي.
6. **الحالات والمصادر من قاعدة البيانات** لا قيمًا في الكود. مصدر الطلب
   `whatsapp`.
7. **سجلّ تدقيقٍ كامل** (append-only) لكل استدعاء نموذجٍ وكل استدعاء أداة، مع
   التوكنز والتكلفة والزمن.
8. **لا ردّ داخل الـwebhook.** يستقبل ويخزّن ويُرجع `200` في أقلّ من ثانية،
   والمعالجة كلّها على الطابور.
9. **التوقيت `Asia/Hebron` واللغة `ar`.**
10. **الصلاحيات عبر `spatie/laravel-permission`**، وتُنشأ في **الهجرة** لا
    البذرة (الإنتاج يشغّل `migrate` وحده).

## 3. القرارات المعتمَدة

خمسة قرارات حُسمت قبل التنفيذ، وثلاثةٌ منها كانت تخالف المسوّدة الأولى:

| القرار | ما اعتُمد | السبب |
|---|---|---|
| دقّة المبالغ | `decimal(15,2)` لا `(15,4)` | المشروع كلّه على `(15,2)`؛ دقّتان للنقود تُنتجان فروق تقريبٍ بين ما يقوله الوكيل وما يُسجَّل في `orders.total` |
| البنية | `app/Modules/` لا `app/Domain/` | المبدأ 13 والمشروع كلّه؛ اصطلاحان متوازيان يشتّتان الصيانة |
| أسماء الجداول | `messaging_channels` لا `channels` | يلتبس المجرّد بـ`ad_channels` وبـ`orders.channel` |
| التأكيد | يحجز المخزون ولا يُرسل لأوبتيموس | التأكيد الكامل يُنشئ **طردًا حقيقيًّا** عند شركة التوصيل؛ ذلك قرار إنسان |
| النموذج | `claude-sonnet-5` | `claude-sonnet-4-6` معرّفٌ لا وجود له وكان سيفشل عند أول نداء |

### 3.1 حدّ صلاحية التأكيد

`confirm_order` ينقل الطلب إلى `confirmed` ويحجز المخزون داخل معاملةٍ واحدة،
**ولا يُرسل الشحنة إلى شركة التوصيل**. الإرسال يبقى بيد الموظفة من شاشة
الطلبات.

والسبب أن تأكيد الطلب في هذا النظام يُطلق `OrderDeliveryDispatcher` فيُنشئ طردًا
فعليًّا عند أوبتيموس. وخطأ الوكيل في هذه النقطة ليس رسالةً خاطئة — بل **بضاعةٌ
تخرج من المستودع إلى الشارع**. فالطلب يُجهَّز كاملًا وينقصه ضغطة إنسان.

### 3.2 التسعير

`get_price` **لا يحسب السعر بنفسه**؛ يُفوِّض إلى مسار تسعير السلة القائم
(`OfferPricing`) كي لا يقول الوكيل رقمًا لا تقبله شاشة الدفع — فالعروض الكمّية
(«٣ بـ١٠٠») وقوائم أسعار التجّار تُطبَّق هناك. وزبون واتساب بلا مسوّق ⇒ سعر
التجزئة.

الواقع الحالي في النظام: عملة واحدة (`store.currency`)، والضريبة مؤجّلة
(ADR-015) و`tax_total` صفر، والتكلفة متوسّط مرجّح متحرّك (ADR-005). فافتراض
«شيكل واحد + سعر شامل الضريبة» مطابقٌ لما هو قائم، لا تبسيطًا مؤقّتًا.

## 4. الجداول

| الجدول | الغرض | ملاحظة حاكمة |
|---|---|---|
| `messaging_channels` | القنوات المربوطة | `ai_enabled` مفتاح إطفاءٍ لكل قناة |
| `channel_contacts` | هوية المُراسِل | `last_inbound_at` أساس نافذة الـ24 ساعة |
| `conversation_statuses` | حالات المحادثة | قابلة للإدارة كبقية الحالات |
| `conversations` | المحادثة | `ai_mode` ثلاثي · `order_id` لقياس التحويل |
| `messages` | الرسائل | `external_id` **فريد** = منع التكرار |
| `agent_runs` | سجلّ استدعاء النموذج | append-only · `cost` decimal(15,4) |
| `agent_tool_calls` | سجلّ استدعاء الأدوات | append-only |
| `product_knowledge` | المعرفة البيعية | `is_ready` يحكم هل يبيعه الوكيل |

`ai_mode` ثلاثيٌّ عمدًا: `active` يردّ · `paused` أوقفه إنسانٌ مؤقتًا ·
`handed_off` سُلّم لموظفة. والمحوَّلة لا يعود إليها الوكيل إلّا بقرارٍ صريح.

## 5. الأدوات

| الأداة | المخرجات |
|---|---|
| `search_products` | النشِطة و`is_ready` فقط |
| `get_product_details` | مواصفات + نقاط بيع + استخدامات + أسئلة شائعة |
| `check_stock` | **المتاح = الرصيد ناقص المحجوز** |
| `get_price` | عبر `OfferPricing` لا حسابًا جديدًا |
| `get_shipping` | من مسار التوصيل القائم (قراءةً فقط) |
| `create_draft_order` | عبر Action إنشاء الطلب نفسه — **لا منطق طلباتٍ موازٍ** |
| `confirm_order` | يعيد فحص التوفّر داخل المعاملة · لا إرسال لأوبتيموس |
| `escalate_to_human` | يوقف الوكيل |

سقف **6 استدعاءات أدوات** لكل `agent_run`؛ التجاوز ⇒ تحويل.

## 6. قواعد التشغيل

**نافذة الـ24 ساعة:** يُفحص `last_inbound_at` **قبل كل إرسال**. خارجها يُرفض
النصّ الحرّ ويُسجَّل السبب ويُعرَض للموظفة خيار قالبٍ معتمَد.

**تجميع الرسائل:** تأخير 5 ثوانٍ يُلغى ويُعاد مع كل رسالةٍ جديدة، بسقف انتظارٍ
كلّي 20 ثانية. ثلاث رسائل ⇒ **ردٌّ واحد**.

**منع التكرار:** `messages.external_id` فريد؛ التعارض ⇒ تجاهلٌ صامت و`200`.

**التحقّق من الـwebhook:** `hub.verify_token` للـ`GET`، و`X-Hub-Signature-256`
بـ`hash_equals` للـ`POST`. الرفض عند الفشل.

**الأخطاء:** محاولتان بتباعدٍ أسّي، ثم تحويلٌ مع اعتذارٍ قصير و`outcome = failed`.

**الشفافية:** أول رسالةٍ صادرة في كل محادثة توضّح أن الردّ آليّ وأن الموظفة
متاحة. قالبٌ قابل للتعديل من اللوحة.


من اللوحة في ثانية عبر `messaging_channels.ai_enabled` بلا نشر.

## 8. ما يُعاد استخدامه ولا يُبنى ثانيةً

| المطلوب | الموجود |
|---|---|
| عقد المزوّد | `MessagingProviderInterface` + `MessagingManager` |
| محرّك واتساب | `WhatsAppCloudProvider` (إرسال + `wamid` + رموز الأخطاء) |
| الـwebhook والتوقيع | `WhatsAppWebhookController` — يُوسَّع للرسائل الواردة |
| الإعدادات | `config/messaging.php` |

الجديد فعلًا: **استقبال الرسائل الواردة** (الحالي يعالج حالات التسليم وحدها).

## 9. معايير القبول

- [ ] الـwebhook يرفض أي توقيعٍ غير صحيح.
- [ ] إعادة الإرسال من ميتا لا تُنشئ صفًّا مكرّرًا ولا ردًّا ثانيًا.
- [ ] ثلاث رسائل خلال ثانيتين ⇒ ردٌّ واحد.
- [ ] لا يذكر الوكيل سعرًا غير مطابقٍ لمخرجات `get_price`.
- [ ] `is_ready = false` ⇒ تحويلٌ لا ارتجال.
- [ ] `confirm_order` ينشئ طلبًا بمصدر `whatsapp` ويحجز المخزون في معاملةٍ
      واحدة، **ولا يُرسل شحنة**.
- [ ] نفاد المخزون بين المسودّة والتأكيد ⇒ لا طلب، واعتذار، وتحويل.
- [ ] بعد التحويل يصمت الوكيل حتى تُعيده موظفةٌ يدويًّا.
- [ ] الإرسال الحرّ خارج نافذة الـ24 ساعة يُرفض ويُسجَّل.
- [ ] لكل استدعاء نموذجٍ صفٌّ في `agent_runs` بالتوكنز والتكلفة.
- [ ] `AI_AGENT_ENABLED=false` يوقف الوكيل ويُبقي الاستقبال والعرض يعملان.
