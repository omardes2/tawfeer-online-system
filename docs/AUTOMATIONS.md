# الأتمتة والمهام المجدولة (Automations & Scheduled Jobs) — Tawfeer Online

> **حالة التنفيذ — مهم:** **لا يوجد أي أتمتة منفّذة الآن.** هذه الوثيقة **تصميمية** توثّق الأتمتة **المستقبلية** فقط؛ تُفعَّل تدريجيًا عبر المراحل المذكورة. لا تعتمد أي جهة على وجودها حاليًا.
>
> **المصادر المُلزِمة:** [`../ARCHITECTURE.md`](../ARCHITECTURE.md) (المبادئ الـ14) و[`DECISIONS.md`](DECISIONS.md) (المصدر الوحيد للحقيقة) و[`EVENTS.md`](EVENTS.md) (كل حدث مُشار إليه هنا معرّف هناك). أي تعارض يُحسم لصالح `DECISIONS.md`.
>
> **قواعد ناظمة:**
> - **الجدولة:** عبر Laravel Scheduler (`schedule:run` كل دقيقة عبر cron النظام)، والعمل الثقيل يُدفع إلى **الطوابير** (ADR-018 / المبدأ 11). لا منطق أعمال حرج داخل مهمة غير متزامنة.
> - **القنوات (المبدأ 13):** كل إرسال خارجي عبر عقد `MessagingContract` (WhatsApp عبر `WhatsAppCloudDriver`) / SMS / Email / إشعار داخل التطبيق (database). لا ربط مباشر بمزوّد.
> - **الإعدادات الديناميكية (المبدأ 9):** كل العتبات والتوقيتات (ساعات المتابعة، حدود إعادة الطلب، نوافذ التذكير...) تُقرأ من `settings`، لا قيم ثابتة في الكود.
> - **الأدوار (المبدأ 12):** المستقبِلون يُحدَّدون بالدور (admin, manager, sales, accountant, warehouse, affiliate, customer)، لا بأسماء/معرّفات مضمّنة.
> - **المراجع الأمامية:** `NOTIFICATION_MATRIX` و`APPROVAL_WORKFLOWS` وثائق مُخطَّطة لم تُكتب بعد.
> - **التدقيق (المبدأ 8):** الأتمتة التي تُنشئ معاملات مالية/مخزونية (مثل احتساب العمولات) تخضع للتدقيق والذرّية كأي عملية (المبدأ 7).

**اصطلاح كل أتمتة:** الغرض · المُشغّل (cron/event) · الشروط · المخرجات/الإجراء · القناة والمستقبِلون · الاعتماديات · الطور.

## 1) تذكيرات الطلبات المعلّقة (Pending Order Reminders)
| البند | التفصيل |
|------|---------|
| **الغرض** | تقليل الطلبات العالقة في حالات ما قبل التأكيد وتسريع المعالجة. |
| **المُشغّل** | مجدول: كل ساعة (`0 * * * *`) يفحص الطلبات؛ يُكمّله حدث `OrderCreated`. |
| **الشروط** | طلب في `new`/`awaiting_contact`/`awaiting_confirmation` (ADR-010) لمدة تتجاوز عتبة `orders.pending_reminder_hours` (Settings)؛ لم يُذكَّر خلال النافذة. |
| **المخرجات/الإجراء** | إشعار داخلي + تصعيد للمدير بعد تجاوز عتبة ثانية؛ تحديث عدّاد التذكير. |
| **القناة والمستقبِلون** | إشعار داخلي/Email لموظف Sales المسند ثم Manager عند التصعيد. |
| **الاعتماديات** | حالات الطلب (ADR-010)، `order_status_history`، إعدادات العتبة. |
| **الطور** | Phase 3. |

## 2) تذكيرات متابعة العملاء (Customer Follow-up Reminders)
| البند | التفصيل |
|------|---------|
| **الغرض** | إبقاء علاقة العميل نشطة بعد التسليم أو نشاط CRM. |
| **المُشغّل** | مجدول يومي (`0 9 * * *`)؛ مغذّى بحدث `OrderDelivered` وأنشطة CRM (`activities.due_at`). |
| **الشروط** | مرور مدة `crm.followup_days` منذ آخر تفاعل/تسليم؛ العميل نشط ولم يُلغِ الاشتراك. |
| **المخرجات/الإجراء** | إنشاء مهمة متابعة (`activities`) وتذكير الموظف؛ رسالة شكر/تقييم للعميل. |
| **القناة والمستقبِلون** | Sales (إشعار داخلي/مهمة)؛ العميل (WhatsApp/Email). |
| **الاعتماديات** | `OrderDelivered`، `activities`، `customers`، Settings. |
| **الطور** | Phase 3 (CRM). |

## 3) تذكيرات السلة المتروكة (Abandoned Cart Reminders)
| البند | التفصيل |
|------|---------|
| **الغرض** | استرجاع مبيعات محتملة من سلال لم تكتمل. |
| **المُشغّل** | مجدول: كل ساعة يفحص السلال؛ يُنهيه حدث `OrderCreated` (تحوّل السلة). |
| **الشروط** | سلة بها عناصر ولم تتحوّل لطلب خلال `cart.abandon_minutes` (Settings)؛ عميل معروف (بريد/هاتف)؛ حد أقصى للتذكيرات. |
| **المخرجات/الإجراء** | تسلسل تذكير (1..N) مع رابط استئناف؛ إيقاف فوري عند `OrderCreated`. |
| **القناة والمستقبِلون** | العميل عبر WhatsApp/Email/SMS. |
| **الاعتماديات** | تتبّع السلة (Phase 3)، `customers`، Settings، عقد الرسائل. |
| **الطور** | Phase 3+ (تسويق). |

## 4) تنبيهات انخفاض المخزون (Low Stock Alerts)
| البند | التفصيل |
|------|---------|
| **الغرض** | تفادي نفاد الأصناف تحت حد إعادة الطلب. |
| **المُشغّل** | حدث `LowStockDetected` (فوري) + فحص مجدول يومي (`0 7 * * *`) شبكة أمان. |
| **الشروط** | `available ≤ reorder_level` لـ(متغيّر × مستودع) (ADR-007)؛ debounce لمنع التكرار. |
| **المخرجات/الإجراء** | تنبيه + بند في تقرير النواقص؛ تمرير إلى أتمتة *اقتراحات إعادة الطلب* (11). |
| **القناة والمستقبِلون** | Warehouse + Manager (إشعار داخلي/Email). |
| **الاعتماديات** | `inventory_stocks.reorder_level`، حدث `LowStockDetected`. |
| **الطور** | Phase 2. |

## 5) تذكيرات استحقاقات الموردين (Supplier Due-date Reminders)
| البند | التفصيل |
|------|---------|
| **الغرض** | تفادي تأخّر سداد فواتير الموردين. |
| **المُشغّل** | مجدول يومي (`0 8 * * *`)؛ مغذّى بحدث `PurchaseInvoiceApproved`. |
| **الشروط** | فاتورة مورد `approved`/`partially_paid` و`due_date` ضمن `purchasing.due_reminder_days` (Settings). |
| **المخرجات/الإجراء** | تنبيه + بند في تقرير المستحقات القادمة. |
| **القناة والمستقبِلون** | Accountant + Manager (إشعار داخلي/Email). |
| **الاعتماديات** | `supplier_invoices.due_date`، حدث `PurchaseInvoiceApproved`. |
| **الطور** | Phase 4. |

## 6) تنبيهات تأخّر التسليم (Delivery Delay Alerts)
| البند | التفصيل |
|------|---------|
| **الغرض** | رصد الشحنات المتأخّرة والتدخّل مبكرًا. |
| **المُشغّل** | مجدول: كل ساعة؛ عدّاد SLA يبدأ من حدث `OrderShipped`. |
| **الشروط** | الطلب `shipped`/`out_for_delivery` وتجاوز زمن الشحن `shipping.sla_hours` بلا `OrderDelivered`؛ قد تُضبط الحالة `delayed` (ADR-010). |
| **المخرجات/الإجراء** | تنبيه + وضع علامة `delayed`؛ مهمة متابعة مع شركة الشحن. |
| **القناة والمستقبِلون** | Sales/Manager (داخلي)؛ العميل (تحديث اختياري). |
| **الاعتماديات** | `shipments.shipped_at`، حالات الطلب، حدث `OrderShipped`. |
| **الطور** | Phase 3. |

## 7) تنبيهات زمن استجابة الموظفين (Employee Response-time Alerts)
| البند | التفصيل |
|------|---------|
| **الغرض** | ضمان الرد على محادثات/طلبات العملاء ضمن SLA. |
| **المُشغّل** | مجدول: كل 15 دقيقة (`*/15 * * * *`) على الصندوق الموحّد. |
| **الشروط** | محادثة `open` بلا رد يتجاوز `inbox.response_sla_minutes` (Settings)، أو طلب `awaiting_contact` تجاوز مهلته. |
| **المخرجات/الإجراء** | تنبيه للموظف المسند ثم تصعيد للمدير؛ رصد للتقارير. |
| **القناة والمستقبِلون** | الموظف المسند ثم Manager (إشعار داخلي/Email). |
| **الاعتماديات** | `conversations`/`messages` (Phase 3+)، حالات الطلب، Settings. |
| **الطور** | Phase 3+ (Messaging). |

## 8) ملخّصات المبيعات اليومية (Daily Sales Summaries)
| البند | التفصيل |
|------|---------|
| **الغرض** | لقطة يومية لأداء المبيعات. |
| **المُشغّل** | مجدول يومي نهاية اليوم (`0 23 * * *`). |
| **الشروط** | وجود نشاط طلبات لليوم؛ الإيراد المعترف به عند `delivered` (ADR-010a). |
| **المخرجات/الإجراء** | تقرير يومي (عدد الطلبات، المبيعات، المتوسط، المرتجعات، الأعلى مبيعًا). |
| **القناة والمستقبِلون** | Manager/Admin (Email/داخلي)؛ التكلفة/الربح تُحجب بلا `pricing.view_cost` (ADR-013). |
| **الاعتماديات** | `orders`، `invoices`، أحداث `OrderDelivered`/`OrderReturned`. |
| **الطور** | Phase 3 (Reports). |

## 9) تقارير الأداء الأسبوعية (Weekly Performance Reports)
| البند | التفصيل |
|------|---------|
| **الغرض** | مقارنة أداء الفرق/القنوات/المسوّقين أسبوعيًا. |
| **المُشغّل** | مجدول أسبوعي (`0 8 * * 6` — السبت). |
| **الشروط** | تجميع بيانات الأسبوع المنقضي. |
| **المخرجات/الإجراء** | تقرير: مبيعات حسب القناة (`web`/`manual`/`marketer`)، أداء Sales، أفضل المسوّقين، معدّل الإرجاع. |
| **القناة والمستقبِلون** | Manager/Admin (Email + لوحة KPI). |
| **الاعتماديات** | `orders`، `commissions`، `returns`، بيانات القنوات (ADR-010). |
| **الطور** | Phase 3+ (Reports). |

## 10) تقارير الأرباح الشهرية (Monthly Profit Reports)
| البند | التفصيل |
|------|---------|
| **الغرض** | قياس الربحية الشهرية (إيراد − COGS − مصاريف). |
| **المُشغّل** | مجدول شهري (`0 6 1 * *` — أول الشهر). |
| **الشروط** | إقفال بيانات الشهر السابق؛ COGS محتسب بـ WAC وقت الشحن (ADR-005). |
| **المخرجات/الإجراء** | تقرير ربحية (إجمالي/صافي)، هامش، ربحية المنتج/الفئة/المسوّق. |
| **القناة والمستقبِلون** | Accountant/Manager/Admin (Email)؛ محجوب بلا `pricing.view_cost` (ADR-013). |
| **الاعتماديات** | `inventory_ledger` (WAC/COGS)، `invoices`، المحاسبة (Phase 5)، أحداث `OrderDelivered`/`GoodsReceived`. |
| **الطور** | Phase 3 (مبدئي) → Phase 5 (كامل بالقيود المزدوجة). |

## 11) احتساب العمولات (Commission Calculations)
| البند | التفصيل |
|------|---------|
| **الغرض** | حساب/تحديث عمولات المسوّقين آليًا وفق القواعد. |
| **المُشغّل** | مجدول يومي (`0 2 * * *`)؛ ومغذّى بأحداث `OrderDelivered`/`OrderReturned`/`ProductPriceChanged`. يُطلق حدث `CommissionCalculated` (EVENTS.md §7.1). |
| **الشروط** | طلبات لمسوّقين وفق `commission_rules`؛ الأساس = صافي البند بعد الخصم (ADR-012c)؛ الاستحقاق بعد التسليم (ADR-012). |
| **المخرجات/الإجراء** | تحديث `commissions`: `expected → earned`؛ عكس/تخفيض عند الإرجاع (ADR-012b). **ذرّي (المبدأ 7) ومُدقَّق (المبدأ 8).** |
| **القناة والمستقبِلون** | Affiliate (لوحة/إشعار)؛ Accountant/Manager (مراجعة الاعتماد). |
| **الاعتماديات** | `commission_rules`، `marketer_price` (ADR-006)، أحداث الطلب/الإرجاع. |
| **الطور** | Phase 3 (الاعتماد/الصرف Phase 4). |

## 12) اقتراحات إعادة الطلب للمخزون (Inventory Reorder Suggestions)
| البند | التفصيل |
|------|---------|
| **الغرض** | اقتراح كميات إعادة الشراء لتفادي النفاد. |
| **المُشغّل** | مجدول يومي (`30 7 * * *`)؛ مغذّى بحدث `LowStockDetected`. |
| **الشروط** | `available ≤ reorder_level`؛ حساب مقترح حسب متوسط الاستهلاك ومهلة المورد (Settings). |
| **المخرجات/الإجراء** | قائمة اقتراحات (متغيّر، مستودع، كمية مقترحة، مورد مقترح)؛ تُحوَّل يدويًا إلى `PurchaseOrderCreated`. |
| **القناة والمستقبِلون** | Warehouse/Manager (لوحة/داخلي). |
| **الاعتماديات** | `inventory_stocks`، `inventory_movements` (تاريخ الاستهلاك)، `suppliers`، حدث `LowStockDetected`. |
| **الطور** | Phase 2 (مبدئي) → Phase 4 (تنبؤ أدق). |

## 13) اقتراحات ترويج الراكد (Dead Stock Promotion Suggestions)
| البند | التفصيل |
|------|---------|
| **الغرض** | تحريك المخزون الراكد بطيء الدوران. |
| **المُشغّل** | مجدول أسبوعي (`0 5 * * 0` — الأحد). |
| **الشروط** | `on_hand > 0` بلا حركة `sale_out` منذ `inventory.dead_stock_days` (Settings)؛ مع احترام `min_price` (ADR-006a). |
| **المخرجات/الإجراء** | قائمة أصناف راكدة + اقتراح خصم/`promo_price` ضمن الحد الأدنى؛ تُحوَّل يدويًا لعرض/كوبون. |
| **القناة والمستقبِلون** | Manager/Marketing (لوحة/داخلي). |
| **الاعتماديات** | `inventory_ledger`/`inventory_movements` (آخر بيع)، طبقات الأسعار (ADR-006)، Settings. |
| **الطور** | Phase 3+ (Promotions). |

# جدول ملخّص الأتمتة (Summary)

| الأتمتة (Automation) | نوع المُشغّل (Trigger) | التكرار (Frequency) | القناة (Channel) | الطور (Phase) |
|---------------------|:--------------------:|:-------------------:|:----------------:|:-------------:|
| تذكيرات الطلبات المعلّقة | مجدول + حدث | كل ساعة | داخلي/Email | 3 |
| تذكيرات متابعة العملاء | مجدول + حدث | يومي | داخلي + WhatsApp/Email | 3 |
| تذكيرات السلة المتروكة | مجدول + حدث | كل ساعة | WhatsApp/Email/SMS | 3+ |
| تنبيهات انخفاض المخزون | حدث + مجدول | فوري + يومي | داخلي/Email | 2 |
| تذكيرات استحقاقات الموردين | مجدول + حدث | يومي | داخلي/Email | 4 |
| تنبيهات تأخّر التسليم | مجدول (SLA) | كل ساعة | داخلي (+عميل) | 3 |
| تنبيهات زمن استجابة الموظفين | مجدول (SLA) | كل 15 دقيقة | داخلي/Email | 3+ |
| ملخّصات المبيعات اليومية | مجدول | يومي | Email/داخلي | 3 |
| تقارير الأداء الأسبوعية | مجدول | أسبوعي | Email + لوحة | 3+ |
| تقارير الأرباح الشهرية | مجدول | شهري | Email | 3→5 |
| احتساب العمولات | مجدول + حدث | يومي + فوري | لوحة/داخلي | 3 |
| اقتراحات إعادة الطلب | مجدول + حدث | يومي | لوحة/داخلي | 2→4 |
| اقتراحات ترويج الراكد | مجدول | أسبوعي | لوحة/داخلي | 3+ |

**الإجمالي: 13 أتمتة** — **لا شيء منها منفّذ الآن**؛ تُفعَّل عبر المراحل 2–5.
